# Spec FSD Skill — 引导式功能规格说明助手

## Skill 元信息

| 属性 | 值 |
|:---|:---|
| **名称** | `spec-fsd` |
| **版本** | 1.0.0 |
| **类型** | 人机协作 Skill |
| **配套文档** | 《功能规格说明》（06 模块） |

---

## 触发条件

当用户提出以下请求时使用此 Skill：

- "帮我写功能规格"
- "定义界面交互行为"
- "FSD 怎么写"
- "把用户故事翻译成功能规格"
- "定义页面布局和功能区域"

---

## 核心理念

> **06 只做一件事：把 05 的 User Story 翻译成可实现的界面/交互行为规格。"谁要什么"写在 05；"界面/接口怎么表现"写在本文。**
>
> AI 负责引导提问和结构化整理，人负责提供真实的界面设计和交互决策。

---

## 工作流程

```
用户提出写 FSD 需求
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Step 1: 确认输入来源                                        │
│  AI 操作: 确认 05 UserStory 是否已完成                      │

│ Step 2: 总体布局/界面结构（§1）                              │
│  🛑 AI 不臆造界面设计！                                     │
│  AI 操作: 引导用户描述/画出界面布局                          │
│  👤 用户提供: 界面布局描述或草图                             │
├──────────────────────────────────────────────────────────┤
│ Step 3: 核心功能区域（§2-3）                                │
│  AI 操作: 对齐 US，引导定义交互行为                          │
│  👤 用户提供: 功能列表、触发方式、调用接口                   │
├──────────────────────────────────────────────────────────┤
│ Step 4: 用户输入区域（§4）                                  │
│  AI 操作: 引导定义输入元素和校验规则                         │

├──────────────────────────────────────────────────────────┤
│ Step 5: 错误处理与用户反馈（§5）                            │
│  AI 操作: 引导定义错误码对应的前端展示                       │
│  👤 用户提供: 错误展示文案和方式                             │
├──────────────────────────────────────────────────────────┤
│ Step 6: 状态管理（§6）                                      │
│  AI 操作: 引导定义前端状态变量                               │

├──────────────────────────────────────────────────────────┤
│ Step 7: US → FSD 对齐表（§7）                               │
│  AI 操作: 建立 US 与 FSD 章节的映射                          │
```

## Step 1: 确认输入来源

### AI 操作

1. 检查是否已有 `05-用户故事与验收标准` 的输出
2. 确认需要定义的 UserStory 列表

---

## Step 2: 总体布局/界面结构（§1）

### 🛑 AI 不臆造界面设计

```markdown
🛑 界面布局必须由你（PM/设计师）定义。

请描述或画出：
1. 你的应用长什么样？
2. 用户打开后第一眼看到什么？
3. 有几个主要区域？

参考布局结构：
┌──────────────────────────────────────────┐
│  header: 标题 + [状态指示]                │
├────────────┬─────────────────────────────┤
│  导航区     │  主内容区                    │
│  [列表/菜单]│  A) 空状态提示              │
│            │  B) 数据列表/详情            │
│            │  C) 操作结果反馈             │
│            │  操作区: 输入/按钮            │
└────────────┴─────────────────────────────┘
```

---

## Step 3: 核心功能区域（§2-3）

### AI 操作

对齐 05 US，引导定义交互行为：

```markdown
📋 核心功能区域

对齐 US-001，请定义该区域的交互行为：

| 功能 | 触发方式 | 调用接口 | 行为描述 |
|------|----------|----------|----------|
| {功能1} | {页面加载/点击按钮} | {API调用} | {交互行为} |

不同状态下的显示内容：

| 状态 | 条件 | 显示内容 |
|------|------|----------|
| A 空状态 | {无数据时} | {提示文案} |
| B 有数据 | {有数据时} | {展示方式} |
| C 加载中 | 请求进行中 | {loading状态} |
```

## Step 7: US → FSD 对齐表（§7）

### AI 操作

```markdown
📋 US → FSD 对齐表

| UserStory | 验收标准涉及交互 | 本文章节 |
|-----------|------------------|----------|
| US-001 | {交互行为} | §2 |
| US-002 | {交互行为} | §3 |

⚠️ 请确认：
☐ 每条 US 的交互相关 AC 是否都有对应描述？
☐ 是否有遗漏的交互场景？
```

### AI 操作

汇总所有内容，输出完整的 `06-功能规格说明` 文档。

## 关键行为准则

### AI 可以做

| ✅ 可以做 | 说明 |
|:---|:---|
| 生成布局模板 | 供用户填写 |
| 对齐 US 与功能 | 建立映射关系 |
| 生成错误处理框架 | 供用户填写 |
| 建立追溯关系 | 格式化整理 |

### AI 绝不可以做

| 🛑 绝不可以 | 原因 |
|:---|:---|
| 臆造界面设计 | 不了解用户真实需求 |
| 臆造交互行为 | 需 PM/设计师确认 |
| 自行定义错误文案 | 需与 09 API 对齐 |
| 臆造状态管理 | 需前端开发确认 |
