# Spec Architecture Skill — 引导式系统架构与技术选型助手

## Skill 元信息

| 属性 | 值 |
|:---|:---|
| **名称** | `spec-architecture` |
| **版本** | 1.0.0 |
| **类型** | 人机协作 Skill |
| **配套文档** | 《系统架构与技术选型》（08 模块） |

---

## 触发条件

当用户提出以下请求时使用此 Skill：

- "帮我写架构文档"
- "定义系统架构"
- "技术选型怎么写"
- "定义分层结构"
- "记录架构决策"

---

## 核心理念

> **08 只做一件事：描述模块的系统架构决策和技术选型理由。"用户要什么"在 05/06；"约束底线"在 07；"系统怎么组织、为什么这样组织"在本文。**
>
> AI 负责引导提问和结构化整理，人负责提供真实的架构决策和技术选型。

## Step 1: 确认输入来源

### AI 操作

1. 检查是否已有 `05/06/07` 的输出
2. 确认需要定义的架构维度

---

## Step 2: 架构总览（§1）

### 🛑 AI 不臆造架构设计

```markdown
🛑 架构设计必须由你（TL/架构师）定义。

请提供以下信息：

1. 系统上下文图：
   - 前端应用类型？（Web/Mobile/CLI）
   - 后端框架？
   - 外部服务？
   - 存储引擎？

2. 架构风格决策：
   - 前后端分离还是单体？
   - 部署模式？（单体/微服务）
   - 分层架构？

参考架构图：
┌─────────────────────────────────┐
│       {前端应用类型}              │
└──────────────┬──────────────────┘
               │ HTTP /api/v1/*
               ▼
┌─────────────────────────────────┐
│     {后端框架} Backend            │
│  ┌────────────────────────────┐ │
│  │  {API路由层}                │ │
│  │    ↓          ↓         ↓  │ │
│  │ {业务层}  {存储层}  {其他} │ │
│  └────┬──────────┬────────────┘ │
│       ▼          ▼              │
│  ┌────────┐ ┌──────────┐       │
│  │{外部服务}│ │{存储引擎} │       │
│  └────────┘ └──────────┘       │
└─────────────────────────────────┘
```

---

## Step 3: 后端分层结构（§2）

```markdown
📋 后端分层结构

| 层 | 文件 | 允许做 | 禁止做 |
|----|------|--------|--------|
| Route | {路由文件} | 参数校验、HTTP状态码 | 直接读写存储 |
| Service | {业务文件} | 业务编排、结果组装 | 感知HTTP请求 |
| Provider | {外部服务文件} | 调用外部API | 操作本地存储 |
| Storage | {存储文件} | 数据CRUD | 调用外部API |
```

## 关键行为准则

### AI 可以做

| ✅ 可以做 | 说明 |
|:---|:---|
| 生成架构图模板 | 供用户填写 |
| 建议分层结构 | 供用户确认 |
| 引导 ADR 记录 | 提问"为什么选A不选B" |
| 对齐 07 安全需求 | 建立引用关系 |

### AI 绝不可以做

| 🛑 绝不可以 | 原因 |
|:---|:---|
| 臆造架构设计 | 不了解项目约束 |
| 自行决定技术选型 | 需团队确认 |
| 臆造 ADR 决策理由 | 需架构师确认 |
| 自行定义部署方式 | 需 DevOps 确认 |
