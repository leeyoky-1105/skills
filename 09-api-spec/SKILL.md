# Spec API Spec Skill — 引导式 API 接口规格助手

## Skill 元信息

| 属性 | 值 |
|:---|:---|
| **名称** | `spec-api-spec` |
| **版本** | 1.0.0 |
| **类型** | 人机协作 Skill |
| **配套文档** | 《API 接口规格》（09 模块） |

---

## 触发条件

当用户提出以下请求时使用此 Skill：

- "帮我写 API 规格"
- "定义接口契约"
- "API 文档怎么写"
- "定义端点请求响应"
- "定义错误码"

---

## 核心理念

> **本文是全部 API 端点的契约真源。05 定义"用户要什么"，09（本文）定义"后端必须返回什么"，13 的测试断言以本文为准。**
>
> AI 负责引导提问和结构化整理，人负责提供真实的接口定义和字段规格。

```

    │
    ▼

│  🛑 AI 不臆造端点路径！                                     │

├──────────────────────────────────────────────────────────┤

│  AI 操作: 引导定义成功/错误响应格式                          │
```

---

## Step 1: 确认输入来源

### AI 操作

1. 检查是否已有 `05-用户故事` 和 `08-架构` 的输出
2. 确认需要定义的端点列表

---

## Step 2: 端点总览（§1）

### 🛑 AI 不臆造端点路径

```markdown
🛑 API 端点定义必须由你（后端开发）提供。

请列出所有端点：

| # | 端点 | 方法 | 功能 | 成功码 |
|---|------|------|------|--------|
| 1 | {路径} | {GET/POST/PUT/DELETE} | {功能} | {状态码} |
| 2 | {路径} | {方法} | {功能} | {状态码} |

🛑 字段名和路径必须与真实代码一致，AI 不臆造！
```

---

## Step 3: 统一响应规范（§2）

### AI 操作

引导定义响应格式：

```markdown
📋 统一响应规范

### 成功响应

{ "traceId": "tr_abc123...", /* 业务字段 */ }

### 错误响应

{ "error": { "code": "ERROR_CODE", "message": "错误描述", "details": {}, "traceId": "tr_..." } }

### 错误码清单

| HTTP | error.code | 触发条件 | details |
|------|-----------|----------|---------|
| 400 | EMPTY_QUERY | {触发条件} | {} |
| 400 | INVALID_QUERY | {触发条件} | {details} |
| 500 | UPSTREAM_ERROR | {触发条件} | {details} |
```

---

## Step 4: 逐端点详细说明

### 🛑 AI 不臆造字段名和类型

```markdown
🛑 每个端点的请求体和响应体必须由你定义。

对于端点 {方法} {路径}：

**请求体**：

| 字段 | 类型 | 必填 | 约束 | 说明 |
|------|------|------|------|------|
| {字段1} | {string/int/bool} | {是/否} | {约束} | {说明} |

**成功响应**（{状态码}）：

| 字段 | 类型 | 必有 | 说明 |
|------|------|------|------|
| traceId | string | 是 | 链路追踪 ID |
| {字段1} | {类型} | {是/否} | {说明} |

⚠️ 请确认：
☐ 字段名是否与代码一致？
☐ 类型是否正确？
☐ 必填/可选是否准确？
```

---

## Step 5: 参数校验规则汇总（§8）

### AI 操作

汇总所有端点的校验规则：

```markdown
📋 参数校验规则汇总

| 端点 | 字段 | 规则 | 失败 HTTP | error.code |
|------|------|------|-----------|-----------|
| {端点} | {字段} | {规则} | {HTTP} | {code} |
```

---

## Step 6: 输出 API 规格文档

### AI 操作

汇总所有内容，输出完整的 `09-API接口规格` 文档。

---

## 关键行为准则

### AI 可以做

| ✅ 可以做 | 说明 |
|:---|:---|
| 生成端点框架 | 供用户填写 |
| 建议错误码命名 | 供用户确认 |
| 汇总校验规则 | 格式化整理 |
| 对齐 07 NFR | 建立引用关系 |

### AI 绝不可以做

| 🛑 绝不可以 | 原因 |
|:---|:---|
| 臆造端点路径 | 需与代码一致 |
| 臆造字段名和类型 | 需与代码一致 |
| 自行定义错误码 | 需与 07 对齐 |
| 臆造校验规则 | 需与业务一致 |
