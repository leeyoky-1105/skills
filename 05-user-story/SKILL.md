# Spec User Story Skill — 引导式用户故事助手

## Skill 元信息

| 属性 | 值 |
|:---|:---|
| **名称** | `spec-user-story` |
| **版本** | 1.0.0 |
| **类型** | 人机协作 Skill |
| **配套文档** | 《用户故事与验收标准》（05 模块） |

---

## 触发条件

当用户提出以下请求时使用此 Skill：

- "帮我写用户故事"
- "拆分 User Story"
- "定义验收标准"
- "从 PRD 生成用户故事"
- "建立需求追溯关系"

---

## 核心理念

> **本文只做一件事：按用户能理解的子场景拆成多条 User Story，并为每条写清 REQ-ID、验收标准（AC）。**
>
> AI 负责引导拆分和格式化，人负责提供真实的业务场景和验收标准。

---

## 工作流程

```
用户提出拆分用户故事需求
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Step 1: 确认输入来源                                        │
│  AI 操作: 确认 04 PRD 是否已完成                            │
│  👤 用户提供: 04 输出 或 直接描述场景                       │
├──────────────────────────────────────────────────────────┤
│ Step 2: 拆分 User Story                                    │
│  AI 操作: 将 04 场景拆分为 US 列表                          │
│  👤 确认点: 拆分粒度是否合理？                               │
├──────────────────────────────────────────────────────────┤
│ Step 3: 为每个 US 填写字段                                  │
│  AI 操作: 引导填写 REQ-ID、优先级、来源等                   │
│  🛑 不臆造: 不自行填写业务内容                               │
│  👤 用户提供: 真实业务信息                                   │
├──────────────────────────────────────────────────────────┤
│ Step 4: 定义验收标准（AC）                                  │
│  AI 操作: 基于 US 生成 AC 草稿                              │
│  👤 确认点: AC 是否可独立验证？                               │
├──────────────────────────────────────────────────────────┤
│ Step 5: 建立追溯关系                                        │
│  AI 操作: 建立 US → 06/09/11/13/14 的追溯                   │
│  👤 确认点: 追溯关系是否完整？                                │
├──────────────────────────────────────────────────────────┤
│ Step 6: 输出用户故事文档                                    │
│  AI 操作: 汇总所有内容，输出 05 文档                         │
└──────────────────────────────────────────────────────────┘
```

---

## Step 1: 确认输入来源

### AI 操作

1. 检查是否已有 `04-产品需求说明` 的输出
2. 确认核心业务场景列表

---

## Step 2: 拆分 User Story

### AI 操作

将 04 场景拆分为 US 列表：

```markdown
📋 User Story 拆分

基于 04 核心场景，我建议拆分为以下 User Story：

| US 编号 | 故事概要 | 优先级 | 对应场景 |
|---------|----------|--------|----------|
| US-001 | {核心功能1} | P0 | SC-01 |
| US-002 | {核心功能2} | P0 | SC-02 |
| US-003 | {核心功能3} | P0 | SC-03 |
| US-004 | {次要功能} | P1 | SC-04 |

⚠️ 幻觉提醒：
拆分由 AI 推理生成，请确认：
☐ 拆分粒度是否合理？（太粗=难以实现，太细=管理成本高）
☐ 是否有遗漏的场景？
☐ 优先级是否合理？
```

---

## Step 3: 为每个 US 填写字段

### 每个 UserStory 必须包含的字段

| 字段 | 填写说明 | 数据来源 |
|------|----------|----------|
| **需求编号** | 唯一编号，如 REQ-M1-001 | ← 02 采集编号 |
| **故事** | 作为【角色】，我希望【行为】，以便【价值】 | ← 04 PRD 场景拆解 |
| **优先级** | P0/P1/P2 | ← 03 §4 成功标准 |
| **来源** | 对应 03/04 哪一条需求 | ← 03 范围 · 04 场景 |
| **前置条件** | 触发该故事的前提状态 | ← 04 用户流程 |
| **功能对齐** | 对应功能规格 | → 06 FSD · 07 NFR |
| **设计对齐** | 对应架构、接口、数据、安全 | → 08/09/10/11 |
| **验证对齐** | 对应测试用例 | → 13 TC · 14 追踪 |

### 🛑 AI 不自行填写

```markdown
🛑 以下字段必须由你提供真实信息：

对于 US-001：
1. 需求编号是什么？（如 REQ-M1-001）
2. 用户故事描述：
   - 作为______（角色），
   - 我希望______（行为），
   - 以便______（价值）
3. 前置条件是什么？
4. 对应 03/04 的哪一条需求？
```

---

## Step 4: 定义验收标准（AC）

### AI 操作

基于 US 生成 AC 草稿：

```markdown
📋 验收标准（AC）

基于 US-001，我草拟了以下验收标准：

| 验收标准 | 描述 |
|----------|------|
| AC-001-01 | {AI 推理} |
| AC-001-02 | {AI 推理} |
| AC-001-03 | {AI 推理} |

⚠️ 幻觉提醒：
AC 由 AI 推理生成，请确认：
☐ 每条 AC 是否可独立验证？
☐ 是否覆盖了正常分支和异常分支？
☐ 是否与 07 NFR 约束一致？
```

---

## Step 5: 建立追溯关系

### AI 操作

建立需求追溯总索引：

```markdown
📋 需求追溯总索引

| 需求编号 | UserStory | 优先级 | →06 功能 | →09 接口 | →11 安全 | →13 测试 | →14 追溯 |
|----------|-----------|--------|----------|----------|----------|----------|----------|
| REQ-M1-001 | {功能1} | P0 | §____ | ____API | §____ | TC-____ | 行____ |
```

---

## Step 6: 输出用户故事文档

### AI 操作

汇总所有内容，输出完整的 `05-用户故事与验收标准` 文档。

---

## 关键行为准则

### AI 可以做

| ✅ 可以做 | 说明 |
|:---|:---|
| 拆分 User Story | 标注为草稿 |
| 生成 AC 草稿 | 供用户确认 |
| 建立追溯关系 | 格式化整理 |
| 生成文档框架 | 按模板组织 |

### AI 绝不可以做

| 🛑 绝不可以 | 原因 |
|:---|:---|
| 臆造用户故事内容 | 不了解真实业务 |
| 自行决定优先级 | 需 PM 确认 |
| 臆造 REQ-ID | 需与 02 编号一致 |
| 自行填写追溯关系 | 需与下游文档对齐 |
