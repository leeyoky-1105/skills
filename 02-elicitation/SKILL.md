# Spec Elicitation Skill — 引导式需求采集助手

## Skill 元信息

| 属性 | 值 |
|:---|:---|
| **名称** | `spec-elicitation` |
| **版本** | 1.0.0 |
| **类型** | 人机协作 Skill |
| **配套文档** | 《需求来源与采集记录》（02 模块） |

---

## 触发条件

当用户提出以下请求时使用此 Skill：

- "帮我采集需求"
- "记录需求来源"
- "整理会议纪要中的需求"
- "帮我做需求调研"
- "记录用户访谈内容"

---

## 核心理念

> **需求采集是所有 Spec 文档的起点。AI 负责结构化引导提问和整理记录，人负责提供真实的需求信息。**
>
> 此 Skill 绝不臆造需求内容。所有痛点、需求、行动项必须来自用户提供的真实信息。

---

## 工作流程

```
用户提出需求采集需求
    │
    ▼
┌──────────────────────────────────────────────────────────┐
│ Step 1: 确认采集范围                                        │
│  AI 操作: 了解项目背景、采集目标                            │
│  👤 用户提供: 项目名称、采集对象、已有素材                   │
├──────────────────────────────────────────────────────────┤
│ Step 2: 会议纪要采集（S-01）                                │
│  AI 操作: 引导提问会议信息、痛点、需求                       │
│  👤 用户提供: 会议时间/人员、痛点列表、需求列表              │
├──────────────────────────────────────────────────────────┤
│ Step 3: 邮件/聊天沟通采集（S-02）                           │
│  AI 操作: 引导提问补充沟通记录                               │
│  👤 用户提供: 邮件/IM 中的关键需求信息                      │
├──────────────────────────────────────────────────────────┤
│ Step 4: 用户访谈采集（S-03）                                │
│  AI 操作: 生成访谈问题清单，引导记录回答                     │
│  👤 用户提供: 访谈对象信息、回答内容                        │
├──────────────────────────────────────────────────────────┤
│ Step 5: 汇总输出需求采集记录                                │
│  AI 操作: 整理所有采集内容，生成结构化文档                    │
│  👤 确认点: 需求列表是否完整？优先级是否准确？               │
└──────────────────────────────────────────────────────────┘
```

---

## Step 1: 确认采集范围

### AI 操作

1. 了解项目背景和采集目标
2. 确认已有的需求素材（会议纪要、邮件、访谈记录等）
3. 确定采集维度（会议/邮件/访谈）

### 👤 需要用户提供的信息

```markdown
在开始需求采集之前，我需要了解：

1. 这个项目的核心业务是什么？
2. 你已经有哪些需求素材？（会议纪要？邮件？聊天记录？）
3. 你希望通过哪些方式采集需求？
   ☐ 会议纪要整理
   ☐ 邮件/IM 沟通记录
   ☐ 用户访谈
4. 采集结果将用于哪个 Spec 模块？（通常是 → 03 立项提案）
```

---

## Step 2: 会议纪要采集（S-01）

### AI 操作

引导用户逐步提供会议信息：

```markdown
📋 会议纪要采集

请提供以下信息：

1. 会议基本信息：
   - 会议主题是什么？
   - 会议时间？
   - 会议地点？（线上/线下）
   - 参会人员？（姓名+角色）

2. 痛点记录：
   🛑 痛点必须由用户提供，AI 不臆造！
   - 用户目前最头疼的 2~3 个问题是什么？
   - 这些问题导致了什么后果？（浪费时间？出错？效率低？）
   - 每个痛点的优先级？（P0/P1）
   - 谁提出的？

3. 需求记录：
   - 针对上面的痛点，用户期望系统能帮他做什么？
   - 列出 3~5 条核心需求

4. 下一步行动：
   - 谁负责什么？截止日期？
```

### AI 输出

将用户提供的信息整理为结构化表格：

```markdown
## S-01 会议纪要 — {会议主题}

| 项 | 内容 |
|---|---|
| 时间 | {用户提供} |
| 地点 | {用户提供} |
| 参会人员 | {用户提供} |

### 痛点记录

| 痛点 | 优先级 | 提出人 |
|------|--------|--------|
| {用户提供} | P0 | {提出人} |

### 需求记录

1. **{需求1名称}**：{一句话描述}
2. **{需求2名称}**：{一句话描述}

### 下一步行动

- ☐ {负责人}完成{什么事}（{截止日期}）
```

---

## Step 3: 邮件/聊天沟通采集（S-02）

### AI 操作

引导用户提供补充沟通记录：

```markdown
📧 邮件/聊天沟通采集

除了会议，还有没有邮件、IM 消息等补充的需求说明？

请提供：
1. 发件人/收件人
2. 时间
3. 关键问题摘录
4. 用户反馈的具体问题和期望
```

---

## Step 4: 用户访谈采集（S-03）

### AI 操作

生成访谈问题清单，引导记录回答：

```markdown
🎤 用户访谈采集

请提供以下信息：

1. 访谈基本信息：
   - 访谈对象是谁？（姓名+角色）
   - 访谈人是谁？
   - 访谈时间？方式？（线上/线下）

2. 核心问题（AI 预设，用户回答）：
   Q1：平时工作中最耗时的环节？
   Q2：最希望系统帮你解决什么问题？
   Q3：目前是怎么解决这个问题的？（现有方案）
   Q4：对新系统有什么顾虑或要求？

🛑 回答内容必须由用户提供，AI 不臆造！
```

---

## Step 5: 汇总输出需求采集记录

### AI 操作

1. 汇总 S-01/S-02/S-03 的所有内容
2. 整理为结构化的需求采集文档
3. 生成需求优先级建议（供用户确认）

### 👤 确认点

```markdown
⚠️ 请确认：
☐ 痛点列表是否完整？是否有遗漏的关键痛点？
☐ 需求列表是否覆盖了所有痛点？
☐ 优先级划分是否合理？
☐ 下一步行动是否明确？
☐ 是否需要补充更多采集来源？
```

## 关键行为准则

### AI 可以做

| ✅ 可以做 | 说明 |
|:---|:---|
| 生成引导提问 | 帮助用户回忆和整理 |
| 结构化整理信息 | 将用户输入整理为表格 |
| 建议优先级 | 供用户确认 |
| 生成下一步行动模板 | 格式化为待办清单 |

### AI 绝不可以做

| 🛑 绝不可以 | 原因 |
|:---|:---|
| 臆造痛点 | 不了解用户真实业务 |
| 臆造需求 | 不了解用户真实期望 |
| 自行决定优先级 | 需业务方确认 |
| 代替用户填写会议纪要 | 必须基于真实会议内容 |
